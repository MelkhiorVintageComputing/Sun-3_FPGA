# The MMU table tests walk every entry of the segment map (2048 segments x
# 8 contexts) and the page map (4096 entries), with a console poll per
# step; at 20 MHz the segment map write/read test alone is ~4.5 s of
# simulated time.  Test 16 entries instead.  Only the tests' own loop
# counts change: the setup loops around them (0x0fef2196 fills the segment
# map, 0x0fef2254 builds the 1:1 page map the PROM runs on afterwards) are
# left alone.

0fef20fa 07fe 000f
# Page Map Test, write pass and check pass: movel #4095,%d4 -> #15
0fef21c2 0fff 000f
0fef21f8 0fff 000f

# Memory Test (diag switch on only; skipped when it is off): its end address
# is (megabytes found) << 20, and it writes and then reads back every word,
# polling the diag switch per word -- ~10 s simulated for 4 MiB.  moveq #20
# -> #16 tests 64 KiB per megabyte found instead.
0fef28ba 7014 7010

# RAM initialisation (always, diag switch or not): fills every longword of
# the memory found with 0xffffffff, from 0 up to %d1.  At ~2.3 us a longword
# that is ~2.4 s simulated for 4 MiB.  %d1 is a copy of %d2 = (megabytes
# found) << 20, and %d2 is ALSO what the monitor keeps as the memory size
# (0xffffe172, the "NMB memory installed" of the banner) -- so the shift at
# 0x0fef2a94 must not change (it once did here: the banner said 0MB).
# Instead the bound's >= 32 MiB clamp (cmpil/bltw/subil, moot below 32 MiB)
# becomes lsrl #4,%d1: 64 KiB filled per megabyte, still from 0, so the low
# memory the monitor keeps its data in is still initialised.
0fef2a9e 0c81 e889
0fef2aa0 0200 4e71
0fef2aa2 0000 4e71
0fef2aa4 6d00 4e71
0fef2aa6 0008 4e71
0fef2aa8 0481 4e71
0fef2aaa 0010 4e71
0fef2aac 0000 4e71

# Keyboard detection: after resetting the keyboard the PROM waits up to 1000
# timer ticks (~1 s) for its reply -- the whole wait, every boot, when there
# is no keyboard.  addil #1000,%d7 -> #10.
